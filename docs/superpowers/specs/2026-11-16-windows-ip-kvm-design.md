# Windows IP-KVM（Rust）设计规格

**日期：** 2026-11-16  
**状态：** 已确认（头脑风暴）  
**范围：** 一期交付远程控制；二期再接本机 AI Agent

## 1. 背景与目标

现有 [Chrome-KVM](../../../README.md) 是浏览器内 **USB 直连 KVM**：采集卡画面走 `getUserMedia`，键鼠走 Web Serial + CH9329，**没有服务端**。远程第三方浏览器无法访问旁路机上的 USB，因此不能把静态页挂到网上就当 IP-KVM 用。

本设计把产品做成 **网络 IP-KVM**：Windows x86 旁路机常驻 Rust 服务，独占采集卡与 CH9329，向内网浏览器提供登录控制页、WebRTC 画面与键鼠注入。长期采用 **双进程**（`kvm-core` + `ai-agent`），但 **一期只做 core 远程控制**，自然语言 Agent 放到二期。

### 1.1 已确认约束

| 项 | 选择 |
|----|------|
| 产品形态 | 网络 IP-KVM（Windows 旁路机常驻被控机旁） |
| 旁路机 | Windows；x86，可有独显/较强 GPU |
| 视频给人看 | WebRTC；有 GPU 则硬编（如 NVENC），否则软编降级 |
| 硬件 | USB 采集卡 + CH9329（+ 可选 LCUS 继电器） |
| 访问 | 仅内网；简单用户名/口令 |
| AI | 目标为本机 GPU VLM + 按需截帧；**二期** |
| 架构 | 方案 2：双进程；一期只交付 `kvm-core` |

### 1.2 非目标（一期）

- 公网直接暴露、复杂 IdP、强制公网 HTTPS 体系
- USB OTG / 虚拟光驱 / 多被控机集群
- 在浏览器里继续用 Web Serial / 用户点选授权 USB
- 本机 VLM、自然语言遥控、云端模型兜底
- 迁移完整五语 i18n、OCR 面板、串口终端页（可后续再搬）

## 2. 总体架构

```
[被控机] HDMI ──► USB 采集卡 ──► Windows 旁路机
                 CH9329 USB ──┘         │
                 继电器(可选) ──┘         │
                                         ├─ kvm-core（一期交付）
                                         │    · 采集 → GPU 硬编(优先) → WebRTC
                                         │    · CH9329 / ATX
                                         │    · 登录 + 控制页 (LAN)
                                         │    · 本机 API：grab_frame / 键鼠 / 状态
                                         │
                                         └─ ai-agent（二期）
                                              · 本机 VLM；按需截帧 → 结构化动作 → 调 core

[内网浏览器] ──HTTP(S) LAN──► 登录控制页：WebRTC + 键鼠（二期再加对话）
```

**原则：** 人看的连续流与 AI 观察拆开。AI（二期）只 `grab_frame`，不把整路视频送进模型。

## 3. kvm-core（一期核心）

旁路机上 **唯一** 访问采集卡与串口的进程；同时服务控制页与（二期）Agent。

### 3.1 模块

| 模块 | 职责 |
|------|------|
| `capture` | 打开 USB 采集卡，产出帧；供编码与 `grab_frame` |
| `encode` | 优先 GPU 硬编，否则软编；输出给 WebRTC |
| `webrtc` | 信令 + 媒体；浏览器只收流 |
| `hid` | CH9329 状态机（队列、ACK、绝对/相对鼠标、降级）；串口独占 |
| `atx` | 可选 LCUS 短按/长按 |
| `session` | 内网用户名口令 → session/token；一期可单会话（新登录踢旧） |
| `api` | 键鼠、ATX、`grab_frame`、状态；给人用 WebSocket，给本机 Agent 用 HTTP 或 WS |
| `static` | 托管登录页与控制页 |

### 3.2 一期对外能力

- **人：** 登录 → WebRTC 看画面 → 键鼠事件注入 HID；可选 ATX
- **本机 API（为二期预留并在一期实现最小集）：** `grab_frame`（jpeg/png）、键鼠类操作、`atx_press`（若启用）、`get_status`
- **互斥（预留策略）：** 二期 Agent 跑任务时可锁定人工输入；一期至少定义接口，默认仅人工控制

### 3.3 协议与复用

- CH9329 / ATX 行为与字节级语义对齐现有 `ch9329.js`、`atx-relay.js` 及 `test/ch9329.test.js` 等样例
- 不在浏览器使用 Web Serial；设备由 core 按本地配置打开（设备名 / COM 口）

## 4. 分期与 ai-agent（二期）

| 期 | 交付 |
|----|------|
| **一期** | 仅 `kvm-core`：WebRTC + CH9329 + 可选 ATX + 内网登录控制页 + 本机动作/截帧 API |
| **二期** | `ai-agent`：本机 GPU VLM；自然语言 → 截帧 → 结构化动作 → 调 core；控制页对话 UI |

二期循环（预告，不实现）：用户指令 → `grab_frame` → VLM 输出结构化动作 → 校验执行 → 再截帧确认；可停止并 `releaseAllKeys`；危险 ATX 可二次确认。WebRTC 人流与 Agent 无关。

一期控制页可为 AI 侧栏留位（隐藏/禁用），避免二期大改布局。

## 5. 控制页 UX 与错误处理（一期）

### 5.1 结构

- 登录页 → 控制页
- 主区：WebRTC 画面；键鼠作用在画面上
- 状态栏：视频 / 串口 / 编码方式（硬编或软编）
- 设置：采集设备、串口、分辨率/码率、鼠标绝对/相对等
- ATX 按钮（已配置继电器时）
- AI 入口：隐藏或灰显

交互语义尽量对齐现 Chrome-KVM（绝对坐标映射到画面 content rect、相对鼠标、全屏、常用组合键）。不再出现「授权 Web Serial」。

### 5.2 错误与降级

| 情况 | 行为 |
|------|------|
| 采集卡丢失 | 状态栏告警；重试打开；停流并提示 |
| CH9329 无应答 | 队列/ACK；多次失败可降级只发不等并提示 |
| 无 GPU 硬编 | 自动软编；状态栏标明；可降分辨率/帧率 |
| WebRTC 失败 | 明确错误提示，不静默黑屏 |
| 登录失败 | 提示；口令仅存旁路机本地配置 |
| 会话 | 一期单会话：新登录可踢旧 |

## 6. 仓库、配置与测试

### 6.1 仓库边界

- 在本仓库增加 Rust 工作区（如 `kvm-core/`），与现有静态站 **并存**
- 保留现有 JS 与测试作协议金标准；一期不删除 GitHub Pages 静态版

### 6.2 配置与运行

- 本地配置：口令、默认视频/串口设备、编码偏好（优先 GPU）
- 内网监听（如 `0.0.0.0:<port>`）；文档说明防火墙放行
- 一期单一启动入口拉起 `kvm-core`

### 6.3 测试

| 层 | 内容 |
|----|------|
| 单元 | CH9329 编解码、队列与 ACK、坐标映射；对照现有 JS 测试样例 |
| 集成（无硬件） | 登录、mock 串口、`grab_frame` 测试图、键鼠入队 |
| 手工（有硬件） | WebRTC 观感、绝对/相对鼠标、组合键、拔插恢复、软编降级 |
| 暂缓 | AI、自动点 BIOS 的 E2E、公网压测 |

### 6.4 一期成功标准

内网另一台电脑的浏览器登录后，能流畅观看被控画面并用键鼠操作；有 GPU 时走硬编；延迟达到「可操作」，而不是「隔几秒一张截图」。

## 7. 风险与开放实现细节

实现计划阶段再钉死、但不改变本规格方向的细节：

- Windows 采集具体 API（Media Foundation / ffmpeg / 其他）与 WebRTC 栈选型（如 GStreamer / 其他 Rust 绑定）
- 硬编 API 与「无 GPU」探测方式
- 控制页是复用改写现有 HTML/JS 还是新前端（须保持第 5 节 UX 语义）
- session 存储与口令哈希的具体方案（须满足「仅 LAN + 本地配置」）
