## Context

See proposal.md - Why。当前实现集中在静态页 `index.html` / `settings.html` 与 `ch9329.js`：Web Serial 写 CH9329 协议帧。绝对移动已走 `0x04`，但松键按键位错误、设置语义颠倒、坐标换算未扣 video 偏移/黑边；相对点击包与绝对移动混用。本次只闭合桌面绝对路径。

## Goals / Non-Goals

**Goals:**

- 绝对模式松键正确、语义与 UI 一致、坐标映射可测
- 改动局限在现有三文件，不引入构建工具或新依赖

**Non-Goals:**

- 相对模式（`0x05`）完整实现与 BIOS 专项
- 串口过滤、分辨率 `exact`、粘贴等其它痛点
- 改动 CH9329 芯片出厂配置（假定默认协议传输 + 复合键鼠可用）

## Decisions

### 1. 语义真相源：`mouseClickMode === "absolute"` 表示绝对

- **选择**：设置 value `absolute` / `relative` 与中文文案一一对应；构造时 `mouseAbsolute = (mode === "absolute")`。
- **备选**：保持现有反转逻辑只改正文案——拒绝，双重反转难维护且易再错。

### 2. 松键与按键状态：绝对包按键位置零

- **选择**：`mouseupAbsolute` 按键字节改为 `0x00`；按下左/右/中仍为 `0x01` / `0x02` / `0x04`；移动包继续携带 `clicked.command` 以支持拖拽。
- **备选**：松键时重发带坐标的完整状态机（One-KVM 风格）——本轮可不做，先修错误位；若实测拖拽仍不稳再升级。

### 3. 坐标：`getBoundingClientRect` + 内容框映射到 0..4095

- **选择**：统一用 `clientX/clientY`；用 video 的 bounding rect；按 `object-fit`/实际 `videoWidth/videoHeight` 与元素尺寸计算 letterbox，得到画面内归一化坐标，再 `floor(n * 4095)` clamp 到 `0..4095`。
- **备选**：继续用 `offsetWidth` + `event.x`——已知全屏/黑边会偏，放弃。

### 4. 绝对模式滚轮

- **选择**：优先在 `0x04` 包的滚轮字节发送；若现有硬件/包路径短期难改，允许临时保留相对滚轮包，但 MUST 不改变按键位与上次绝对坐标语义，并在 tasks 中标注验证项。
- **备选**：强制本轮改完绝对滚轮——若阻塞主路径可降级，规格已允许「不破坏绝对状态」的替代。

### 5. 相对模式

- **选择**：本轮不实现相对移动；修正文案后，选「相对」可保持现有相对点击行为或明确提示「未完整支持」，避免伪装可用。推荐：文案对齐后相对路径维持现状并在设置旁短提示「桌面请用绝对」。

## Risks / Trade-offs

- [部分采集卡/页面布局仍有黑边算法边界] → 先覆盖常见 `contain` 等比黑边；极端 CSS 缩放后续再补
- [用户本地已存错误 `mouseClickMode` 值] → 保存时按新语义写入；旧「反转」配置可能导致一次选错，可用文案+默认绝对缓解
- [绝对滚轮与相对滚轮混用残留] → 桌面点选/拖拽优先验证；滚轮作为次要验收

## Migration Plan

1. 部署静态资源（GitHub Pages / 本地打开均可）
2. 建议用户打开设置页重新选择「绝对模式」并保存
3. 回滚：还原三文件即可，无服务端状态
