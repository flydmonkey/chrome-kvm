## Context

项目是无构建步骤的静态页面：各脚本以全局变量加载，同时用 `module.exports` 导出给 `node --test` 做单元测试，没有任何依赖。控制页逻辑原先几乎都在 `kvm-page.js` 里，直接操作 DOM 与浏览器 API，难以测试。动机见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 修复相对位移丢失、降级不恢复这类协议层问题，并用单元测试锁住
- 让视频、串口在设备拔插和设置变化后自行恢复，不需要刷新页面
- 把控制页里可脱离 DOM 的判断抽出来，使其可以单元测试

**Non-Goals:**
- 不引入构建工具、框架或测试依赖
- 不改变 CH9329 协议之外的硬件行为，不做固件层面的调整
- 不改动绝对模式的坐标映射规则

## Decisions

### 相对位移在队列里累加，超出单包范围时拆出余量插到队首
绝对坐标被覆盖没有问题（只关心最终位置），相对位移被覆盖就是丢距离。备选方案是每次位移都单独入队，但串口慢时队列会无限增长、延迟越积越大。累加既不丢距离，又保持队列长度有界。余量放到队首而不是队尾，保证同一段移动连续发出。按键入队时清掉「待合并」指针，后来的位移只能开新包，从而不会越过按键。

### 降级只影响普通命令，查询命令永远等应答
降级是为了让不回应答的芯片也能用；但如果连查询也不等，就再也没有机会发现芯片恢复了。让查询（低频、本来就需要结果）始终等待，收到任何应答就恢复，是代价最小的探测方式。备选的定时探活会额外占用串口带宽，被否决。

### 视频恢复靠 `devicechange` + 防抖 + 设备 ID 比对
画面轨道一旦结束不会自己复活，只能重新请求。一次插拔会触发多次 `devicechange`，所以防抖 800ms 后枚举设备，只有所选采集卡确实回来了才重开，避免无关设备插拔刷出一串失败。用「正在打开」与「待重开」两个标志串行化打开过程，保证同一时间只有一路占用采集卡。

### 设置同步用 `storage` 事件
设置页保存会写 localStorage，`storage` 事件只在其它标签页触发，正好对应「设置页保存、控制页响应」，本页自己回写波特率不会触发自身。对比新旧设置，按灵敏度、视频参数、串口三部分分别处理；备选的 BroadcastChannel 需要两边都改且收益相同。

### 串口重连用代数计数丢弃过时连接
串口是独占的，连接过程是异步的。每次开始连接递增代数，完成时代数不一致就立即关闭归还，避免两次快速保存导致新连接被旧连接挡住。

### 非阻塞提示条取代 `alert`
`alert` 会抢走焦点，浏览器随之丢失按键状态，被控端上按着的键全部松开，还会退出指针锁定。提示条按类别去重、按级别决定自动消失时间，满足所有原先用弹窗的场景。

### 抽出 `page-logic.js` 承载可测逻辑
设置差异计算、媒体参数生成、逐个尝试串口、错误文案、录制格式选择、粘贴结果文案这些纯逻辑抽到独立模块，沿用项目「全局变量 + `module.exports`」的双导出方式，`kvm-page.js` 只负责接线。

## Risks / Trade-offs

- [硬件回报率取样只在安全上下文可用] → 不可用时自动回退普通移动事件，功能不受影响，只是延迟略高
- [60fps 依赖采集卡实际能力] → 用偏好而非硬性条件请求，不支持时退回较低帧率但保住分辨率
- [设置同步依赖同源 localStorage] → 设置页与控制页同源部署，跨源场景不在支持范围内
- [部分行为未在真实硬件上验证（硬件回报率手感、60fps、串口切换重连、授权弹窗、串口芯片名）] → 逻辑部分已有单元测试与浏览器冒烟测试覆盖，硬件相关行为需在实机上回归

## Migration Plan

已保存的配置无需迁移：新增的帧率字段缺省或非法时按「默认」处理，原有字段语义不变。回滚只需还原代码，不涉及数据变更。
