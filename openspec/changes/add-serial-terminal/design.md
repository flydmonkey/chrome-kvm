## Context

动机见 proposal.md。和设计相关的现状：

- 项目是纯静态页面，脚本都是普通 `<script>`，同一页面的脚本共用全局作用域。可单测的纯逻辑单独放成 UMD 风格的文件（如 `atx-relay.js`、`profiles.js`），在 node 下用 `require` 测。
- `i18n.js` 只负责选语言和查词典，词典由各语言文件 `I18n.register()` 进来；语言选择存在 `chrome-kvm-lang`。`theme.js` 负责明暗主题，选择存在 `chrome-kvm-theme`。两者都不依赖页面里的其它脚本。
- `test/page-scripts.test.js` 要求所有 `kvm-*.js` 都由 `index.html` 加载，并检查列出的页面里脚本没有重名的顶层声明、没有加载时用到后加载脚本的函数。
- 发布脚本 `build-site.js` 会把 git 跟踪的文件全部复制到 `_site/`，并给 HTML 引用的本地 js、css 加上内容哈希。
- 串口是独占的：一个串口被某个页面打开后，其它页面再 `open()` 会失败。

## Goals / Non-Goals

**Goals:**

- 终端页可以完全独立使用，和控制页、设置页只有跳转关系，不共享状态。
- 挑串口时不向任何候选串口写字节。
- 对现有页面的改动只限于设置页的「工具」Tab 和其中的入口按钮。

**Non-Goals:**

- 同一页面开多个终端（需要时开多个标签页）。
- 和控制页联动：不排除 CH9329 正在用的串口、不跟被控机配置走、不在控制页里嵌入终端。
- 手动控制 DTR、RTS 引脚（见 Open Questions）。

## Decisions

### 1. 独立页面，只复用不依赖页面状态的两个基础模块

终端页加载 `theme.js`、`theme.css` 和 `i18n.js`，不加载 `settings-store.js`、`notices.js`、`profiles.js` 等任何和控制页、设置页状态有关的脚本。

- **为什么复用主题和语言**：用户在设置页选了深色主题和日文，打开终端却是浅色中文，体验割裂。这两个模块只读写各自的 `localStorage` 键，复用它们不会让终端页依赖其它页面的逻辑。
- **为什么不复用 `notices.js`**：它的按钮文案在主词典里，终端页不加载主词典。终端页的提示需求很简单（连接状态、错误、多行粘贴确认），用终端下方的一行状态栏实现即可（左边状态和消息，右边常驻的芯片建议）。
- **为什么不做成设置页的一个 Tab**：设置页的保存、授权、切换配置、切换语言都会刷新整页，终端连接会被反复打断；独立页面没有这个问题。

### 2. 词典独立：`terminal-locales/<语言>.js`

终端页不加载 `locales/` 下的主词典，只加载 `terminal-locales/` 下五个语言文件，每个文件 `I18n.register(code, {...})`。主词典不增加终端文案，只增加设置页「工具」Tab 的名字和入口卡片的几条文案。

- 这样主词典和终端词典互不影响，以后删掉终端功能也只需删目录。
- 测试里对终端词典单独检查五种语言的键是否齐全。

### 3. 终端渲染用 xterm.js，固定版本放进 `vendor/xterm/`

使用 `@xterm/xterm` 5.5.x 的 UMD 构建（`xterm.js`、`xterm.css`）和 `@xterm/addon-fit`，连同 MIT 许可证文件一起提交。终端页用普通的 `<script>`、`<link>` 引入；页面本身就是终端，不需要按需加载。

- **为什么不自己写**：交换机的菜单式配置界面、`top`、`vi` 都依赖光标定位、颜色、备用屏幕等 ANSI 序列，自己实现的工作量和 bug 面都远超接入一个库。
- **为什么不用 CDN**：项目承诺不连外网也能用，OCR 的 Tesseract 也是这么做的。
- **为什么不选 hterm**：体积更大、和 Chrome OS 绑得更紧，文档和生态不如 xterm.js。
- 收到的数据直接以 `Uint8Array` 交给 `term.write()`，xterm.js 自己处理跨数据块的 UTF-8 拆分。
- `fit` 插件在 `resize` 时重算行列数。

### 4. 代码拆成纯逻辑和页面脚本两层

- `terminal.js`（UMD，可在 node 下测）：参数常量和 `normalize()`、存储读写、回车与粘贴的换行转换、多行判断、候选串口过滤、5MB 日志环形缓冲、日志文件名生成。
- `terminal-page.js`：工具栏控件、xterm 初始化、串口挑选与读写循环、断线重连、辅助操作、离开确认。

不用 `kvm-` 前缀，避免被 `page-scripts` 测试当成控制页脚本。

### 5. 串口挑选：只打开不写入，有歧义就交给浏览器的选择框

```
  已授权串口
     |  按保存的 VID/PID 过滤（本页会话里用户选过的串口优先）
     v
  逐个 open()（不写任何字节）
     |
     +-- 恰好 1 个能打开 ----> 使用它
     +-- 0 个 ---------------> 提示不存在或被占用
     +-- 多于 1 个 ----------> 全部关闭，显示「选择串口」按钮
                                  |
                                  v
                    navigator.serial.requestPort({filters: [VID/PID]})
                    （Chrome 的选择框会显示 COM5、ttyUSB1 这类系统端口名）
                                  |
                                  v
                    记为本页会话的 chosenPort，之后重连直接用
```

- **为什么不发探测包**：终端另一头是被控机的 console，任何探测字节都会被当作输入。
- **为什么用浏览器选择框**：Web Serial 的 `getInfo()` 只给 VID/PID，两个 CH340 在自己做的列表里一模一样，只有浏览器的选择框能显示系统端口名。`requestPort()` 需要用户手势，按钮点击正好提供。
- 控制页正占着 CH9329 时，那个串口 `open()` 会失败而被自然跳过，所以「终端和 CH9329 同型号、控制页已连上」的情况不需要两页通信也能挑对。

### 6. 读写循环

- 打开：`port.open({baudRate, dataBits, stopBits, parity, flowControl})`，进入 `readable.getReader()` 的读循环，每块数据同时交给 `term.write()` 和日志缓冲。
- 写：打字、粘贴的数据串在一个 Promise 队列上，用同一个 `writer`，避免并发 `getWriter()` 抛错，也保证多行粘贴的顺序。
- 主动断开：标记 `closing`，`reader.cancel()`、释放 writer、`port.close()`。读循环结束时看到这个标记就不当作意外断开，并清掉「需要重连」标记。
- 意外断开：读循环抛错或 `navigator.serial` 的 `disconnect` 事件命中当前串口时，标记 `lost`，终端里写一行暗色提示。`connect` 事件到来时如果 `lost` 且用户没点断开，按当前参数重新走第 5 节的流程，优先使用 `chosenPort`。
- 改参数：已连接时先主动断开再按新参数打开，xterm 实例不重建，历史输出保留。
- 离开：连接中注册 `beforeunload` 触发浏览器的离开确认；`pagehide` 时尽力关闭串口，没关成浏览器也会在卸载时释放。

### 7. Break、粘贴、复制、日志

- Break：`setSignals({break: true})`，等 250ms，再 `setSignals({break: false})`，后者放在 `finally` 里。
- 粘贴：在终端容器上拦截 `paste` 事件的捕获阶段，`preventDefault()` 后走自己的流程；按钮粘贴用 `navigator.clipboard.readText()`。换行统一成 `\r\n|\r|\n` 后替换为「回车发送」的设置；超过一行时在状态栏显示「确认发送 N 行 / 取消」，确认后整体入写队列。
- 复制：xterm.js 的 `getSelection()` 写入 `navigator.clipboard`。
- 日志：环形缓冲存原始 `Uint8Array` 块，总量超过 5MB 时从头部丢块（最后一块按需截断）；保存时拼成 `Blob` 下载，文件名形如 `serial-2026-10-23-161530.log`。

### 8. 配置存储

终端页只用自己的键 `chrome-kvm-terminal`：

```js
{
    deviceId: {usbVendorId, usbProductId},
    label: "WCH CH340 (1A86:7523)",
    baudRate: 115200, dataBits: 8, parity: "none", stopBits: 1,
    flowControl: "none", newline: "cr"
}
```

读出时经 `normalize()` 校验。串口的显示名由终端页自己按 VID/PID 生成（常见芯片的小表放在 `terminal.js` 里），不引用 `device-filter.js`，以免依赖主词典里的文案。

### 9. 入口放在设置页新增的「工具」Tab

设置页 Tab 栏在「电源」之后加「工具」，`data-tab="tools"`，图标用扳手。面板里是一张「串口终端」卡片：标题、一句简介（「通过 USB 转串口连接交换机、路由器、开发板或服务器的 console 口，不需要采集卡和 CH9329」）、「打开串口终端」按钮，按钮 `window.open("terminal.html", "_blank")`。

现有 Tab 机制只需要两处配合：`settings-page.js` 里的 `SETTINGS_TABS` 加上 `"tools"`，否则 `#tools` 会被当成未知分类退回「常规」；点击、方向键切换和网址里的 `#` 定位都由现有的 `bindTabs()` 自动处理。文案（Tab 名、卡片标题、简介、按钮）加到主词典，五种语言各一套。控制页完全不动。

- **为什么不放控制页**：控制页没有设置时会直接跳去设置页，只接串口设备、没有采集卡和 CH9329 的用户根本进不了控制页。
- **为什么单独开一个 Tab**：串口终端不是一项「设置」，混在常规、视频里不好找；单独的「工具」Tab 语义清楚，以后其它独立小工具（比如硬件扩展路线图里的几项）也有地方放。
- **「工具」Tab 下面仍然显示底部的「保存」按钮**：现有按钮行在所有 Tab 下共用，这里不做特殊处理。在「工具」Tab 点保存和在其它 Tab 点效果一样，不会造成问题。
- **为什么在新标签页打开**：设置页表单里可能有没保存的改动，在当前标签页跳走会丢掉。需要同时看画面的用户，可以从控制页的齿轮进设置页，再开一个新标签页。

## Risks / Trade-offs

- [控制页连 CH9329 时会对 VID/PID 匹配的串口逐个发探测包。终端页没开、终端转接线又和 CH9329 同为 CH340 时，探测包可能发到被控机的 console 上] → 终端页常驻一行建议，README 建议终端用 FT232、CP2102、PL2303 等不同芯片的转接线。探测包是 `57 AB` 开头的短二进制帧，对登录提示通常只造成一次失败的输入，但对处于配置模式的网络设备仍有风险，文档要写清楚。这是「不和现有代码耦合」的直接代价：要彻底解决，需要控制页知道终端用了哪个串口，而两个页面拿不到对方的串口对象。
- [继电器同理：终端页没开时，继电器挑串口也可能打开终端的转接线] → 继电器只在能打开的候选恰好一个时才发指令，多于一个就报错不发，风险低于 CH9329 探测；同样靠「终端用不同芯片」规避。
- [RS232 是 ±12V 电平，直接接 TTL 模块会烧坏模块] → README 写清楚 TTL 和 RS232 两种接法各买什么线。
- [只接了 TX/RX/GND 三根线时开硬件流控会一直发不出去] → 默认不开流控，README 常见问题里说明。
- [xterm.js 给仓库增加约 300KB] → 只有终端页加载；固定版本，升级时人工替换。
- [Chrome 打开串口时可能会默认拉起 DTR/RTS，带自动复位电路的开发板（Arduino、部分 ESP32 板）会在连接时被复位] → 作为已知行为写进 README；是否提供 DTR/RTS 开关见 Open Questions。

## Migration Plan

没有数据迁移，新存储键不存在时按默认参数、未选择串口处理。回滚只需撤销提交，`chrome-kvm-terminal` 留在 `localStorage` 里不影响其它页面。

## Open Questions

- 是否需要 DTR、RTS 的手动开关，用于复位或让开发板进入下载模式。可以等有人反馈再加，不影响本次的结构。
- 是否允许填写列表以外的自定义波特率（如 74880）。目前只用固定列表，后续加一个自定义输入不影响其它部分。
